# レベル3：パーソナル復習コーチ

## 基準と既存機能

基準mainは `59e7b888f81a1c319ccbd7ce39fee3a738d476c5`（PR #3統合済み）。問題データは100問、ID 1〜100、全問6部構成の解説で、今回問題データは変更していません。

元の保存キーは `gkentei-trainer-v3-exam-original`。保存内容は `history: [{id, ok, at}]`、`wrong: [問題ID]`、`sets: 完了セット数` でした。`at` は回答時に生成したISO日時です。

通常は100問を混ぜて5問、従来の弱点優先は未回答と誤答を同じ候補群として5問、復習はwrongのIDから最大5問を選びます。元の選択肢番号と表示順を分離したシャッフルと採点は維持しています。

正式サイトはGitHub Pagesのmain・ルートを公開する構成です。今回その設定は変更せず、専用ブランチからPRを作ります。`index.html` と同じ場所に新規の `coach.js` が必要です。

## 機能

ホームは「学習ダッシュボード → 今日の学習 → パーソナル復習コーチ」の順で表示します。「今日のおすすめ復習5問」を追加。3問を通常表示し、残り2問は折りたたみで表示します。各カードは問題ID・分野・問題文・理由・優先度を持ちます。開始した問題にも開始時点の理由を表示します。

推薦は新規の `coach.js` に分離した純粋関数で計算します。外部AI・有料DB・ネットワーク送信は使いません。日付は端末の現地日付です。

## 集計と復習日

履歴配列に記録された順番を回答順として扱います。不明な日時を推測して並べ替えません。元の有効な履歴行と追加フィールドを保持し、問題ごとに次を計算します。

| 保存する集計 | 内容 |
|---|---|
| totalAttempts | 読み取れる総解答回数 |
| correctCount / wrongCount | 累計正解・不正解数 |
| lastCorrect | 最後の回答の正誤。記録がなければnull |
| correctStreak | 最後から連続する正解数 |
| lastAnsweredAt | 最後の回答に有効な日時がある場合だけ保持 |
| nextReviewAt | 最後の日時と復習間隔から導出。不明ならnull |
| recentResults | 直近最大3回の正誤 |
| legacyReview | 回答記録はないが従来のwrongに残る問題の区別 |

回答時間は導入していません。過去の回答時間や日時を補いません。最後の回答に日時がなければ、それ以前の日時を「最後の日時」として代用もしません。

| 最後の結果 | 目安の間隔 |
|---|---:|
| 不正解 | 1日 |
| 1回連続正解 | 3日 |
| 2回連続正解 | 7日 |
| 3回連続正解 | 14日 |
| 4回以上連続正解 | 30日 |

日付をカレンダー上で進め、原則として回答時刻を引き継ぐ推奨日時を導出します。選定ではその「目安日」が端末の日付で今日以前かを判定します。厳密な時刻到来ではなく日単位にすることで、同日の途中で期限時刻が来ただけで5問が変わらないようにしています。夏時間でも日付単位の間隔です。

これは調整可能な初期ルールで、科学的に最適な間隔や習熟を保証しません。直近の誤答・繰り返した誤答は、目安日前でも優先する場合があります。

## 推薦の計算

まず、次のどれかに該当する問題を復習候補にします。

- 最後の回答が不正解
- 回答記録なしで従来の復習リストに残っている
- 復習の目安日が今日以前
- 累計で2回以上不正解で、現在は2回連続正解に達していない
- 最後の回答から14暦日以上経過し、現在は2回連続正解に達していない

復習候補を先に並べ、5問に足りなければ、まず読み取れる解答記録がない問題、さらに足りなければその他の問題から補充します。2回以上連続正解した問題は、目安日前に過去の誤答や経過日数だけで優先候補へ戻しません。各グループ内では次の点数の降順です。ルールは `WEIGHTS` と `rankQuestion()` に分離しています。

| 要素 | 点数 |
|---|---:|
| 最後の回答が不正解 | +100 |
| 回答履歴のない従来復習リスト | +90 |
| 累計不正解数 | +20×回数÷（1＋連続正解数）、回数は最大5回まで |
| 復習の目安日到来 | +60 |
| 目安日を過ぎた日数 | +1×日数、最大30日 |
| 最後の回答からの暦日数 | +0.5×日数、最大60日 |
| 読み取れる解答記録がなく従来復習リストにもない | +35 |

表示する優先度は100点以上が高、40点以上が中、それ未満が低です。復習候補を先にするため、異なるグループ間では点数だけの順にはなりません。

同点の場合は「端末の日付＋履歴の指紋＋問題ID」の決定的なハッシュ順、最後はID昇順にします。タイブレークは当て推量の正答率などではありません。同日・同履歴・同じ端末の時差設定なら同じ5問になり、日付や回答が変われば再計算します。

空の履歴では100問すべてが同点になるので、日付に応じたランダムに近い5問です。同じIDは選びません。5問未満の問題集合でも、重複で埋めず利用可能な数だけ返します。

ホーム表示時・おすすめ開始時・5問完了時・Safariでホームが再表示された時に再計算します。日をまたいで開き直しても更新されます。出題中の5問と理由は開始時点で固定し、途中で入れ替えません。

## 理由の根拠

前回の不正解、直近最大3回での不正解数、累計不正解数、日時から求めた経過日、従来の復習リスト、読み取れる記録の有無から作ります。

日時がない問題に「7日経過」「期限到来」と表示しません。破損等で読めない場合に未学習と断言しないよう、「読み取れる解答記録がないため」と表示します。履歴のない旧wrongだけの問題では、回数や前回の正誤を捏造せず「復習対象として保存されているため（回答記録は不明）」とします。

## 保存互換性と保護

同じキーに従来のhistory・wrong・setsを残し、`schemaVersion: 2` と `questionStats` を追加します。集計は回答保存時に更新し、読み込み時は保存済み集計を鵜呑みにせず履歴から再計算します。旧版も従来フィールドを読めます。古いアプリが追加フィールドを落としても、履歴があれば再集計できます。

- 初期表示だけでは、保存データを上書きしません。
- 不正なJSON、行の形式不正、扱えないID等は集計から除きますが、書き換える前に元の文字列を `元のキー.recovery.時刻` へそのまま退避します。
- 退避できなければ元のキーを上書きしません。保存容量不足・アクセス拒否時も停止せず、画面内の学習を続けて警告します。
- この版より新しいschemaVersionは上書きしません。
- 別タブ等で保存内容が変わった場合も上書きを停止します。この画面の記録をバックアップしたうえで再読み込みする案内を出します。複数タブの自動マージは行いません。
- 「学習履歴をバックアップ」は利用者の操作でJSONを端末へ保存します。現在のデータと、起動時に読み取った元の文字列を含めます。外部へ送信しません。危険な上書きを避けるためインポートは実装していません。
- 履歴のリセットは従来の確認付きボタンだけです。復習コーチが履歴を自動削除することはありません。退避コピーも自動削除しません。

Safariの通常のサイトデータが残っていれば再起動後も利用できます。ただし閲覧データ削除・プライベートブラウズの終了・OSやブラウザによるデータ削除まで防ぐことはできません。バックアップファイルは個人の学習履歴なので、保管先に注意してください。
